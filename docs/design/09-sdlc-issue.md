## Design

### Summary

Kanbei is a self-hosted, single-user, always-thinking ledger agent. It runs offline in one NIC-less microVM on the owner's host, owns the RTX 3090, and serves the owner's own model through llama.cpp. There is no managed model API and no network interface: the world reaches Kanbei only through six closed channels (Inbox read-only, Vault read-only, Todo read-write size-capped, Chat over vsock with TLS in the VM, CSR over vsock, Search over vsock, capped). Code enters the VM only through a human-merged `smores56/kanbei` commit pinned in nix-config's `flake.lock`. The canonical acceptance journey is life admin: ingest, reconcile, advise, and maintain the owner's todo list.

The design is a **truth-first canonical ledger with a deliberately narrow authority model**, supported by convergence, attention, Git, and security planes. It is not a universal truth engine. Human intent, approvals, amendments, vetoes, curation, and promotion are canonical authority records. Observations are canonical records of what a source appeared to contain, not automatically true statements about the world. Semantic memory is a rebuildable projection of canonical inputs and curation. Effect and activation receipts record attempted and observed effects; replay never repeats external effects.

### Problem

One person needs an inspectable, continuously reconciled model of what is true, what should change, and what agents are doing, while the harness reshapes itself within explicit external-effect boundaries. The system must ingest heterogeneous project and web state, preserve exact human intent and evidence, explore and execute nested work, reconcile external commits without clobbering speculative history, maintain useful derived memory without pretending memory is truth, and allow live self-modification without letting agents manufacture consent or edit the enforcement boundary.

The environment is hostile to naive agent designs, and the split removes the two assumptions the earlier draft leaned on (a trusted remote provider and an unrestricted network). Instead:

The host kernel, the frozen trust root, the human, and the audit sink are trusted. **The agent process itself is the adversary.**

### Goals / Non-goals

Goals:

1. **Canonical evidence with narrow authority.** Answer why the system believes something, who decided it, and what changed.
2. **Rebuildable semantic memory.** Useful entities, claims, conflicts, and disclosure projections with stable source identities and reversal by projection version.
3. **Intent-to-work execution.** Exact intent → versioned interpretations → scoped approvals → nested work → evidence-gated completion → autonomous reconciliation, with escalation where interpretation, acceptance, or a prior decision changes.
4. **Durable agent loops.** Persistent event- and timer-driven loops with idle backoff, policy concurrency, hard global ceilings, soft per-loop budgets, journaled model I/O, and deterministic recovery — with no second workflow authority.
5. **Safe-enough external effects.** At-least-once attempts, idempotency keys, durable journals, `outcome_unknown`, and explicit compensation; never exactly-once claims.
6. **Bounded self-modification.** Declarative lenses, views, and settings activate live at the next turn; executable tools, plugins, and projections activate only after a human approval receipt, always with capability diffs, atomic scope flips, health checks, and rollback.
7. **A closed boundary.** No NIC, no credential, no resolver, and exactly six channels; canonical writes behind the frozen append API; writable roots limited to the declared mounts; ceilings human-owned.
8. **Stable, exfiltration-proof presentation.** A static CSP-locked shell that returns JSON only and renders model text with no remote resources and no auto-linking.
9. **Operational durability.** Canonical SQLite and whole-object CAS on an in-guest LUKS volume, image backup, verifiable restore, indefinite retention by default.
10. **Measured quality.** Zero-tolerance gates plus measured reconciliation quality, life-admin task success, lane latency, ingest freshness, and UI usefulness.

Non-goals: multi-user authority, multi-host canon, offline sync, or tenancy; any network path beyond the six channels (no cloud model API, no generic search API from the VM, no Kanbei-to-nanobot channel); universal domain modeling or arbitrary source onboarding (ingest adapters are closed to Git, HTTP resource, web search, and local filesystem and run in their own VMs); a theorem prover, adversarial court, delta algebra, attention market, or CRDT truth model; full deterministic LLM regeneration or replay of external side effects; TUI parity; autonomous irreversible effects such as payments, public posting, or force-push; agent editability of the enforcement path; exactly-once delivery; confidentiality of search query strings beyond the cap, filters, and judge; chunk-level blob dedup, mandatory signatures, fixed retention schedules, or concrete numeric ceilings.

### Proposed design

**Six kernel contracts.** Record (append-only typed components; canonical at rest), Effect (scoped activation/disposal/compensation; owns resources, not authority), Projection (deterministic or explicitly asynchronous derived state with coverage), Capability (mediated filesystem, process, network, model, secret, append operations), Loop (durable execution, subscriptions, branches), View (renderer-neutral catalogs, artifacts, gestures). Every canonical byte passes through the frozen append API.

**Frozen trust root.** Canonical append/integrity path and single sequencer; the six-channel host surface and its code (Inbox reader, Vault reader, Todo writer, Chat server, CSR handler, Search client); the Monty host-call boundary and sandbox supervisor; global ceilings and governor; receipt verification as one frozen admission path (effect receipts, approval binding and server-issued evidence hashes, tier resolution, coverage evaluation); activation/rollback supervisor; audit sink; startup verifier; and the minimal read-only consent surface plus its human-gesture endpoint. The consent surface is origin-isolated from the shell's data views, serves from a separate origin inside the VM, and mints the single-use `consentDigest` preimage; mutable code may deep-link to it and cannot supply its evidence, scope, or ruling. Executable candidates activate only after a human approval receipt that binds candidate digest, capability diff, scope, and expiry.

**Records and ledger.** Open, namespaced, independently versioned components (`kb.<domain>/<name>@x.y.z`). Mandatory envelope fields are only `recordId`, sequencer-assigned `seq`, `epochId`, `recordedAtUs`, `prevHash`, sorted components, and `recordHash`; `recordHash` is excluded from hashed bytes. Canonicalization is deterministic via RFC 8785 JCS, UTF-16 code-unit key/type ordering, no duplicate component types, and integers/digests encoded as specified. `record_hash = SHA-256("kanbei.record.v1" NUL canonical_json)`. Unknown optional components survive byte-identically; a required component major version no operational projection understands is rejected with `UNSUPPORTED_COMPONENT`. Only `recordedAtUs` is a mandatory semantic clock; valid, observed, published, derived, and expiry times are optional typed components; file `mtime` is never capture time. Corrections and retractions append; they never mutate.

Authority is a closed class set: `human_authority`, `delegated_authority`, `observation`, `candidate_claim`, `derived_proposal`, `effect_receipt`, `activation_receipt`, `security_action`, `coordination`, `lifecycle`, `kernel_generation`. A stable-domain namespace confers no authority: writes are authorized by the triple (authority class, appender role, component type). Agents and plugins may append observations, candidate claims, derived proposals, and policy-approved desired state; they cannot append promotions, attestations, effect/activation receipts, security actions, kernel generations, or spoof `kb.core/*`. Principal-to-class rules are enforced at append.

The append API accepts typed intents — `append`, `link`, `transition`, `retract`, `quarantine` — each carrying an authenticated actor, `IsolationScope`, idempotency key, and optional `expectedEpochId`. The transaction is: `BEGIN IMMEDIATE`; authenticate and validate scope; validate shape, schemas, authority, and blob visibility; compute request digest; idempotency lookup (same key/same digest returns the prior result, different digest rejects with `IDEMPOTENCY_CONFLICT`); assign `seq` and non-decreasing `recordedAtUs` (clamp backward clock jumps, raise `clock_skew`); canonicalize and insert; apply the typed intent; validate domain invariants (no record carries both desired and observed; at most one `owns` parent; acyclic links; derivations point backward and cannot cite retracted/suspect inputs); enforce admission quotas; update operational projections in the same transaction; insert idempotency row, update head, optional checkpoint; commit; notify projection workers. Failure leaves `ledger_head` unchanged. `CHAIN_MISMATCH` is fatal and forces read-only repair.

Canonical payload types carry **no `state` field**. Current state is a lifecycle projection over appended `kb.core/lifecycle@1.0.0` records keyed by `(family, subject_id)`, computed at a basis `seq`, with `guard_digest` committing the canonical inputs the frozen path evaluated. Every `transition` must match its family's complete actor/event/guard table in a single lifecycle registry; unlisted transitions reject even with valid state-name strings. Lease families (`wakeup`, timers, inbox) use compare-and-set `expect.from` plus fencing tokens. There is no reactivation row for approvals or overrides.

One sequencer assigns one global sequence; `seq` orders recording, not causation, and explicit `causes`/`owns`/`derives`/`retracts`/`blocks`/`informs` links carry partial order, so no distributed clocks are required. The hash chain is per epoch; normal operation has one epoch, physical erasure opens a new one. Genesis predecessors and checkpoint digests use distinct domain-separated hashes. Verification replays from the last trusted checkpoint; mismatch, missing sequence, duplicate hash, or idempotency inconsistency blocks writes. No global causal total order is inferred.

**Persistence.** Canonical state: `ledger.sqlite` (WAL, `synchronous=FULL`, foreign keys, one writer) with operational projections committed atomically beside it; `projections/<name>.sqlite` for rebuildable semantic stores; `cas/` for blobs; `spool/channels/` for channel spools — all on the in-guest LUKS volume under `/var/lib/kanbei/`. Image content (kernel, static UI, model weights, fixtures) is read-only Nix output from the flake-pinned commit; no secret material is stored in the VM. Blobs are immutable whole objects in an OCI-layout store behind a replaceable `BlobStore`; publication is bytes → manifest → ledger; per-object and total admission ceilings apply. Backup is an encrypted image snapshot with an online SQLite checkpoint; restore verifies every reference and rebuilds derived indexes. Retention defaults to indefinite; physical erasure is an exceptional epoch-producing operation.

Retention defaults to indefinite. Physical erasure is an exceptional human-authorized operation that freezes the prior epoch, records an `erasure_digest` commitment over what was erased, tombstones rows (keeping identity/hash/links resolvable), deletes covered CAS bytes and backups, and rebuilds projections; copies outside Kanbei's control cannot be guaranteed removed. Backup takes an online SQLite point-in-time snapshot immediately before the filesystem backup, pauses CAS GC, copies snapshot and immutable blobs (writes may continue), resumes GC, writes a manifest with checkpoint digest and blob catalog, and on restore verifies every reference and digest before serving reads. No destructive automatic down migration.

**Desired/observed and work.** Desired and observed are separate optional linked components on separate records with distinct authority paths; no entity must have both across records but may have both over time. Desired generation increases monotonically; `observedGeneration` is a cursor, absence means unknown, not healthy. No Kubernetes-shaped object. Each work item has exactly one ownership parent, an arbitrary causal DAG, acceptance criteria, a scope, and a max effect class. `WorkItem` is immutable; the work projection selects the current immutable `WorkGeneration` (accepted interpretation hash, resolved plan hash, acceptance digest, completion subject hash). `acceptance_digest` hashes the sorted criteria; `completion_subject_hash` binds accepted interpretation hash + generation + acceptance digest and is null until an interpretation is accepted. Work states are a validated lifecycle machine (`draft` … `completed`/`failed`/`abandoned`/`superseded`/`reopened`) with tier-dependent promotion.

Completion requires a `CompletionClaim` for the selected generation with, per criterion, at least one verified `pass` whose subject hash matches; each evidence kind has a verification rule (`test_run`, `diff`, `observation`, `human_attestation`, `effect_receipt`, `replay_digest`). `inconclusive` is not `pass`; required blockers must be `completed`; any required effect still `outcome_unknown`, `failed_terminal`, or unresolved `denied` blocks promotion. A cited receipt whose outcome contradicts `pass` fails the provenance gate. `forbidden` is an admission denial, not a work state; a human-only scoped expiring `TierException` may downgrade it to `approval_required`.

External changes are recorded immediately and reconciled autonomously where non-conflicting. Divergences are classified `non_conflicting`, `semantic_conflict`, `decision_conflict`, or `acceptance_conflict`; only the first two reconcile autonomously, the latter two escalate. Effect admission checks the observed generation against the expected basis; a mismatch denies and emits a divergence (silent-clobber gate). Speculative history is never rewritten to match external state; external commits are observations, never approvals.

**Intent, autonomy, and approval.** The intent anchor is immutable and exact, with source spans; amendment and veto are new linked anchors. Interpretations are immutable, cite spans and assumptions, and carry scope, plan reference, acceptance criteria, and a hash covering all fields including the resolved plan. Acceptance binds the hash; any edit produces a new hash and a new decision. Consequential branches require an accepted interpretation unless human-owned policy says otherwise; declared exploration may run with a null interpretation hash only under `automatic` with no consequential effect class, and adoption is explicit. Chat authority inference (advisory/directive/corrective/question/social) is a derived candidate claim; the message is canonical and its force is not. A literal directive cannot bypass `approval_required`; reclassification appends a superseding inference.

Autonomy policy is human-owned, versioned, and declarative, with tiers `automatic < review_after < approval_required < forbidden`. The effective tier is the most restrictive matching rule (priority breaks ties only within the same tier); no match or unknown blast radius yields `approval_required`; `forbidden` dominates. Effect-class ordering is a policy-owned partial order, and coverage compares classes only through it; incomparable classes have no coverage. Agents may append `TierProposal`; only human acceptance writes a new policy. A claim or confidence value never grants authority.

There is one global decision queue grouped by intent anchor and policy-clamped deadline. `dedupe_key` includes the server-computed evidence-set hash, so different evidence sets never collapse. Displayed request sets are frozen at a `batch_snapshot_seq`; later arrivals form separate rows. A batch requires the same anchor and evidence hash, no `forbidden` item, non-conflicting constraints, and snapshot membership; it emits one receipt per request with its own bound hashes and never unions scopes. Per-receipt revocation supports partial batch revocation. Request intake is rate-limited and deadlines are clamped, so callers cannot set urgency.

Approval requests are immutable coordination records; only a human principal appends an approval receipt. The frozen consent surface renders the ruling-independent manifest, appends a canonical `ConsentDisplayManifest` with a single-use session-bound token, and mints `consentDigest` over the exact display preimage. The gesture endpoint reloads that preimage, recomputes the digest and the ruling commitment over digest + ruling + token hash, verifies origin, CSRF, token single use, expiry, and all bound hashes, and consumes the token atomically with the ruling. A mutable-UI-supplied digest is rejected. `approve`/`amend` create receipts; `reject`/`defer` record rulings without receipts; `defer` requeues with a new clamped deadline; no receipt is reactivatable. The coverage predicate recomputes, at every effect admission and promotion, receipt liveness and expiry, ruled work and current generation ids, anchor, completion subject, resolved `Plan` hash and recorded refinement chain, current server-computed evidence hash, scope containment, effect-class ≤ work ≤ receipt, actual dispatch target, criteria equality, and constraint satisfaction. The predicate is never cached beyond a transaction and is frozen.

Agents may override **failed constraints** with a recorded rationale and a proven weaker-or-equal replacement, because constraints express delegated intent. Binding hashes, scope, effect class, envelope, tier, `reject` rulings, and all hard boundaries are not overridable. Weakening is decidable only through the registered constraint kinds, per-kind rules, explicit policy `weaker_than` edges, and renamable-kind conditions; anything else rejects with `CONSTRAINT_LATTICE_UNPROVEN`. Override counts are computed from canonical records; exceeding a per-receipt or per-loop limit appends an escalation that raises the effective tier to at least `approval_required`. Human revocation blocks future effects but does not erase completed ones.

**Semantic memory.** The current semantic graph is derived, versioned, and rebuildable; source identities are stable. Agents append merge, split, alias, contradiction, relink, and scope proposals, applied only non-destructively and reversible by projection version. A scoped resolver prefers a working claim for action but preserves contested status and alternatives, enforces memory scope at read time, and excludes claims whose projection row is suspect/retracted or whose source or derivation records appear in ledger-side suspect rows or active quarantine — the union, evaluated at read time, regardless of rebuild progress. Self-reported confidence is uncalibrated metadata and cannot affect authority or promotion. Coverage and pending work accompany every semantic read.

Retraction appends a record and takes effect immediately: bounded in-transaction suspect propagation, `pending_closure` for the remainder, an asynchronous incremental rebuild, and preserved history. A second retraction of the same target rejects; a new derivation from a retracted input rejects. Suspected poisoning appends a `security_action` quarantine over a scope that excludes all affected claims, derived artifacts, and disclosure nodes from retrieval and presentation. Human promotion appends a linked human-attested assertion naming canonical source ids and derivation hashes plus a stable projected claim key — never the projection-local `claimId` — and does not certify objective truth. Disclosure is an arbitrary versioned DAG with coverage, provenance, and staleness; no fixed world/feature/task levels, and disclosure depth is never conflated with work depth.

**Execution and durability.** A loop is a durable, persistent entity, not a turn; wakeups, timers, and idle backoff decide when it reasons. Wake signals coalesce last-wins per dedupe key; payload messages queue FIFO. Default concurrency is one running wakeup; self-wakeups require a progress marker or declared no-op, and repeated no-progress wakes double backoff and escalate `loop_stalled`. Timers fire once by CAS with a scheduler fencing token; missed timers fire once, latest-only. A watchdog appends an idle trigger for quiescent loops and a per-step heartbeat budget moves stalled running loops to `interrupted`, never holding the watchdog off.

Hard ceilings are a single operator-configuration shape in the frozen trust root, reserved before lane, channel, ingest, and sandbox calls: GPU lanes and lane seconds, ingest bytes and batches per source, CAS and state bytes, Todo bytes, chat rate, search queries and query length, and loop concurrency. Held plus committed never exceeds a ceiling, and exhaustion denies and suspends rather than queueing unbounded work. Per-loop budgets are soft, agent-overridable with rationale within a human-owned multiplier and never past hard ceilings. Concrete values are mandatory configuration informed by measurement; no phase runs with ceilings absent.

Effects journal before dispatch. One canonical receipt envelope carries journal-assigned `effect_id`, attempt, channel-host/supervisor-minted `request_id`, fencing token, idempotency key, capability, target, producer class, outcome, digests, redaction coverage, and — only for completion subjects — the completion subject hash. Only the frozen journal, channel host, supervisor, or system appender may write receipts. Ambiguous termination yields `outcome_unknown`, which is terminal for automation, blocks promotion, and is resolved only by a read-only probe or a human-authorized new attempt with a new id.

Checkpoints are replay bases, not full copies: loop, wakeup, branch, basis `seq`, deterministic state digest, open effects, inbox cursors, pending timers, model-I/O head, context projection version, and plugin-state refs. They are taken after each wakeup, before any effect dispatch, after approval mutations, and before a fork; digest mismatch blocks resume. `ModelCall` records exact **post-redaction** semantic and wire payloads, parameters, usage, output events, and reasoning availability (`provided`/`redacted`/`absent`); credential-bearing bytes are not persisted by default, and a pre-redaction commitment may be recorded. Hidden chain-of-thought is never synthesized. A retry is a new call.

Undo appends a new branch from a verified checkpoint and marks the target undone; no record, checkpoint, or model I/O is deleted and descendants are preserved with a derived `contains_undone_ancestor` flag. Undo never undoes an approval or tier. Cross-agent branch sets compute the transitive causal/blocking closure, record affected work, and default to `consistency="none"`; `global_cut` is admissible only with a shared basis and no later external effect. External effects are residual and compensated, never undone.

Replay is three distinct contracts: `projection_rebuild` (canonical inputs → projection digest), `execution_replay` (checkpoint + recorded model I/O and effect results, no model or capability calls), and `presentation_replay` (view events → timeline at a declared basis). Digest mismatch appends divergence and does not advance coverage.

Restart recovery verifies the chain and checkpoint, acquires a fenced single-writer lease, appends `RecoveryEpoch`, resolves every `in_flight` effect before resuming loops, rebuilds mismatched projections, requeues inbox items, re-arms and dedupes timers, converts expired heartbeats to `interrupted` and resumes only from that wakeup's own verified checkpoint (else appends `recovery_degraded`), re-evaluates expiry/revocations/overrides/budgets, and closes as `healthy` or `degraded`. There is no second workflow authority.

**Self-modification.** Two lanes. Declarative documents (context lenses, view catalogs, themes, keybinds, settings, disclosure rules, budgets) activate at the next turn boundary with the running turn pinned, validated for schema, budget, authorized sources, component versions, total disclosure, no presentation of suspect or retracted records as current, no remote reference, no code, and no removal of an anchor, decision affordance, or consent link. Executable candidates (tools, plugins, executable projections) are immutable generations with a dependency lock against image artifacts, eight ordered validations (manifest/schema, dependency resolution, static capability scan, artifact provenance from the pinned image, dynamic conformance under Monty with channels denied, state-migration dry run on shadow state, security probes, health-plan validation), a capability and dependency diff, a candidate approval request rendered by the frozen consent surface, and on approval a shadow preparation, standby boot with effects gated, drain, atomic pointer flip, post-flip health, and rollback to the retained previous candidate. Nothing bypasses the approval. Code enters the VM only through a human-merged commit built into the image; the VM never builds or fetches.

Plugins receive only `PluginContext` handles (append, query, scoped state, effect scope, projection registrar, capabilities, loops, views, tools, models). Append and actor/scope are materialized from the authenticated channel; direct SQLite access is denied by no handle, no mount, and single-writer append, and an attempt is a structured security violation that quarantines the candidate. Views may not append gestures; judgment gestures route only through the frozen consent surface and its endpoint. Scoped state is `rebuildable` (pure fold of canonical queries plus recorded effect results) or `checkpointed` (journaled with periodic checkpoints); arbitrary non-replayable durable state fails conformance.

Mutable changes flow through candidate staging: immutable `CandidateManifest`, eight ordered validations (manifest/schema, dependency resolution, static capability scan, sandboxed pinned build, dynamic conformance with external capabilities denied, state-migration dry run on shadow state, security probes, health-plan validation), a capability/dependency diff, human policy for added/broadened sensitive grants, shadow preparation, standby boot with effects gated, drain, atomic pointer flip (write-temp/fsync/rename/fsync-directory), post-flip health, then commit or roll back. `trustRootAccess: true` always rejects; forward-only migrations require an explicit roll-forward decision; external effects remain after rollback and may be `outcome_unknown`. Crash before flip leaves the old pointer; crash after flip re-runs health and may quarantine; rollback is idempotent and never runs a down migration.

Declarative context projections (filters, queries, budgets, summaries, disclosure rules) activate next turn, with the running turn pinned; validation rejects schema/budget violations, unauthorized sources, unknown component versions, rules that present suspect/retracted records as current, non-total disclosure rules, and implicit fallbacks. Executable projection code follows the full plugin candidate path. Every activation appends a receipt and a visibility/hidden diff; human decision views read outside the agent's context scope.

The Nix compatibility gate checks canonical format (refuse newer format), plugin state schema versions (quarantine newer, migrate older on a shadow generation), contract-version ranges, and artifact availability, before activating any scope. Human-approved rollback is allowed only when the older kernel can read the data; otherwise it refuses and offers roll-forward or checkpoint-branch recovery.

**Tools and providers.** Agents see one execution surface: `search`, `list`, `describe`, `execute`; descriptors are versioned, content-digested, scope-filtered, and deterministically ordered. `call` dispatches one function; `program` runs under Monty inside the VM with generated typed host-call stubs. Host calls are effects, recorded and budgeted; the stub set is closed and Monty has no ambient filesystem, network, or subprocess access. Model routing is human-owned policy over local lanes: one `llama.cpp` server, one 128k chat lane and three 32k background lanes from a shared q8_0 KV pool, MTP off, CPU embeddings and reranker, exact post-redaction request/response evidence, no remote provider, no fallback. Search is one provider-neutral contract with TinyFish as the only adapter inside the Search VM: a hit is a locator, not a capture, and the VM holds the only key.

Search and fetch are provider-neutral; TinyFish is one adapter behind the contract. A search hit is a candidate locator, not a capture; only a fetch produces a capture observation, and a snippet is never cited as source content. Provider-native fields and envelopes are preserved; scores are never compared across providers; conditional fetch with `304` advances validators and coverage; documented limits (30 requests/minute, 12,000/day, page ≤ 10) are applied as backpressure before the call; typed failures map `402`→quota, `403`→upstream_forbidden, `429`→rate_limit, `5xx`→transient, and no failure yields a content-bearing observation. Transport is part of provenance.

Model routing is human-owned policy per task class (primary, fallbacks, token/cost/timeout limits, retry rules); normalization covers messages, tool calls, output events, usage, and finish reason without assuming provider equivalence, and provider-specific fields remain in the raw evidence. Requested/completed/failed events are appended and post-redaction payloads stored in the CAS; retries are new calls; global ceilings are hard and per-loop budgets soft.

**Security.** S-1–S-17 fix the adversary as the agent process inside the VM and make the VM boundary, the channel manifest, global ceilings, activation, and audit hard human- or kernel-owned limits. A provider credential never exists in the VM. The KB VM has no NIC, no DNS, and no raw sockets; its only device surface is the six channels. One sandbox instance exists per loop attempt, with only the image, Inbox and Vault (read-only), Todo (capped), scratch, agent state, mutable code, and the allowed channel sockets mounted; start verification refuses a weaker posture or an extra channel. Monty bounds a program's time and memory but is not the security boundary. Effect audit covers channel operations, lane calls, process spawns, activations, and ceiling events; a direct syscall cannot leave the VM. `04-security-deployment.md` is normative for the channel rules, limits, and deployment.

One sandbox instance exists per loop attempt. The supervisor mounts only the image (read-only), Inbox and Vault (read-only), Todo (size-capped), per-sandbox scratch, agent state, mutable code (read-only except the candidate directory), and the allowed channel sockets; the canonical ledger, trust root, other agents' state, and audit sink are withheld. There is no writable project root and no host path beyond the mounts. The supervisor records the actual enforcement class and refuses to start when it is weaker than declared, when an extra share or socket exists, or when the interface list is anything but `lo`.

The only outbound path is the capped Search channel, and it is an accepted residual: a few dozen bits leak per query to TinyFish despite DLP, the judge, and the cap. The Chat channel delivers text to the owner and the Todo channel writes text the owner reads within a size cap.

There is no credential broker. The pre-split broker injected enrolled credentials into outbound requests; the VM has neither credentials nor outbound requests. Surviving mediation moved to where the credential already lives: per-source ingest VMs hold one source's credentials on a read-only block device, parse hostile input, and emit age-encrypted batches to a host writer that Kanbei mounts read-only; the Search VM holds the only remote key, applies DLP and the judge, strips responses to text, and logs every query root-only. Ingest batches are one-way, immutable, ordered per origin, idempotent by digest, and carry a freshness heartbeat.

Deployment fixes the plane: one qemu microVM, 8 GB, no NIC, 3090 by VFIO, in-guest LUKS sealed to a per-VM swtpm vTPM with an offline recovery key. The image, including the frozen trust root, static UI, and model weights, is Nix-built from the pinned commit; mutable state is on the LUKS volume and activated by pointer flip; host artifacts are root-only. `kanbei.sammohr.dev` is a Cloudflare private route reachable only from WARP clients, with edge TLS decryption off and TLS terminating in the VM; a host relay under its own UID carries it; the host tunnel is separate from the cluster tunnel. Access identity and posture plus an in-VM passkey gate it, and loopback is not consent. The CSP shell is static and human-owned; the consent surface is frozen and origin-isolated. A watchdog runs in the VM and on the host, freshness is alerted per source, and backup is an image snapshot.

**Ingestion and interface.** The ingest adapter set is closed (Git, HTTP, search, filesystem) and runs inside per-source VMs that never write canonical storage. Kanbei consumes an `IngestBatchManifest`: one immutable age-encrypted batch per scan, ordered per origin, with coverage, suppression counts, and evidence; the reader publishes entry bodies to the CAS, appends one coverage receipt, then makes observations visible. Every origin carries a freshness heartbeat; a source past its window is labelled stale and alerted. Git material arrives inside batches, so no repository is writable from the VM and a silent external clobber has no path. The UI is a static, human-owned bundle with a strict CSP (`default-src 'none'`, `script-src 'self'`, `connect-src 'self'`, `img-src 'self' data:`, `form-action 'self'`, `frame-ancestors 'none'`), JSON-only API, model text rendered as text nodes with no auto-linking, and zero remote requests for planted images, links, CSS `url()`, or iframes.

The UI is a stable web shell with fixed routes, anchors, action vocabulary, and coordinated graph, delta timeline, and global decision views; themes and contextual components are mutable, but removing an anchor or decision affordance fails health checks. Canonical events stay internal; AG-UI supplies run/interrupt adaptation (one interrupt group at a time, individual canonical rulings inside it), A2UI supplies declarative catalogs with custom graph components over its data model, and MCP Apps supplies the sandboxed artifact boundary with ephemeral view state. Curation gestures append human-authority records; passive navigation appends presentation events only. Arbitrary files are content-addressed with provenance and previews; derived OCR/text/metadata/embeddings/thumbnails remain distinct from raw objects, carry redundant selectors, and become `suspect` immediately when their source is retracted.

**Weaker guarantees stated deliberately.** No exactly-once delivery; no replay of effects; no bit-identical LLM regeneration; no calibrated confidence; no proof of reconciliation correctness; no complete erasure of copies outside Kanbei's control; no confinement beyond the VM for approved code; no security claim for the Monty interpreter; no agent editability of the enforcement path.

### Alternatives considered

- **Architectural center.** Change-first world repository (Git/JJ), convergence-first desired-state reconciler, attention-first decision console, and boundary-first observation plane were all rejected as the center. Git is not a temporal/query/memory engine; free-form intent does not naturally become contracts; rulings have no meaning before memory exists; security is cross-cutting but not the product. Kanbei keeps the adjudicated ledger with narrow authority and makes the other four supporting planes.
- **State substrate.** Pure event sourcing lacks native blobs and taxonomy; XTDB, Datomic, CRDT DAGs, Kubernetes-shaped objects, changesets, streaming engines, lakehouse formats, RDF/OWL, and fine-tuning/RAG alternatives each lose queryability, provenance, valid time, or authority clarity. Kanbei uses an append-only ledger with typed components, blobs, causal links, and explicit projections.
- **Durable execution.** Temporal, Restate, DBOS, LangGraph, Inngest/Cloudflare step memoization, and SDK pause snapshots either cap or discard history, cannot express replay fully, or would become a second workflow authority. Kanbei accepts checkpoint volume and replay cost in exchange for native ledger durability.
- **Semantic memory.** Graphiti/Zep, Mem0, Letta, A-MEM, PROV-O, BoostER-style posteriors, and compaction research do not provide reversible split, calibrated confidence, or rebuild-on-deletion. Kanbei makes confidence uncalibrated metadata and split a non-destructive projection operation.
- **Self-modification.** Cordis/DeepSeek Harness, Erlang hot swap, Home Assistant config entries, Nix generations alone, Emacs live images, VS Code contribution points, and Zed/pen extensions each lack atomic scoped activation, migration policy, or effect accounting. Kanbei borrows patterns, not dependencies, and adds its own candidate protocol.
- **Runtimes and interaction.** Monty, WASI CPython, full CPython, Deno, and vendor programmatic tool calls are not interchangeable; in-process interpreters are explicitly disclaimed as security boundaries. The language and runtime are now fixed by the split: Monty for agent-authored code and Deno for the control plane, with the model-dependent bake-off retired because one fixed local model leaves nothing to compare.
- **Interface and blobs.** AG-UI, A2UI, and MCP Apps are different layers, not competitors; json-render, CopilotKit, AI SDK UI, and ChatKit are framework or hosted layers. Whole-object OCI-layout CAS is chosen over chunked CAS and claim-check stores, accepting the orphan window with strict publication order and reclamation.
- **Security and deployment.** Egress proxies cannot prevent exfiltration when a path exists; Kanbei's answer is the absence of a NIC and a closed channel set. Vault/SPIRE/SOPS/Sigstore and OPA/Cedar/OpenFGA decide but do not enforce here; prompt-on-every-action contradicts the intended autonomy. Enforcement stays in append, channel hosts, supervisor, ceilings, and activation; the one surviving human gate is executable-candidate approval.

### Risks and accepted residuals

Principal risks and mitigations: a channel leak through a NIC, undeclared share, or extra vsock port (closed manifest, start verification, watchdog probe, `ZT-15`); search leakage (cap, DLP, judge, budget, root-only log); injected model text using the browser as a channel (static CSP, JSON only, no auto-linking, `ZT-16`); an approved executable candidate turning malicious (human approval receipt, capability diff, quarantine, rollback); Monty engine compromise or process-wide OOM (VM boundary, host watchdog, ledger recovery); stale sources trusted silently (heartbeats, stale labels, host alert, `ZT-18`); lane starvation (lane governor, hard ceilings); wrong reconciliation (non-destructive operations, projection versions); poisoning (quarantine and rebuild); approval fatigue (deduped queue, review-after); CAS growth (admission ceilings); a nominal vTPM seal (offline recovery key); and ceilings set poorly (operator configuration from measurement).

Accepted residuals, stated explicitly:

1. **Search and channel reach.** Capped, filtered, judged queries still leak a few dozen bits per query; a compromised Kanbei can send the owner Chat text and write Todo text within the cap.
2. **VM escape and host root.** A VM escape, a kernel bug, or host root reads everything; physical separation is the upgrade path.
3. **Approved-code reach.** A human-approved candidate runs with the VM's reach over the mounts and channels; approval is the gate, not confinement.
4. **Interpreter and process failure.** A Monty or supervisor compromise yields the VM, and a process-wide OOM restarts it; both are contained, not prevented.
5. **External effects.** No exactly-once delivery and no effect replay; ambiguity yields `outcome_unknown`.
6. **LLM fidelity.** Hidden reasoning is not promised; replay uses recorded post-redaction I/O and never promises bit-identical regeneration.
7. **Semantic truth.** Derived memory can be wrong; human promotion records attestation, not objective truth.
8. **Poisoning.** Quarantine and rebuild reduce blast radius but cannot guarantee detection or complete removal from derived artifacts.
9. **Erasure.** Physical erasure creates an epoch and covers derived artifacts and backups as far as possible; copies outside Kanbei's control cannot be guaranteed removed.
10. **vTPM seal.** Under direct kernel boot the seal may bind to no measured state; the offline recovery key is the durable path.

### Validation

Validation is evidence-producing. Every run emits an immutable `EvidenceEnvelope` bound to test id, invariants, fixture version, canonical head (`seq` + hash), sequence range, environment fingerprint (host, kernel, runtime, Monty posture, channel manifest digest), seeds, post-redaction lane-recording and artifact digests, outcome (`pass`/`fail`/`inconclusive`/`blocked`), failure class, metrics, and accepted residuals. A run without an envelope is not a result. Sealed datasets are `journey-v2`, `ingest-v1`, `append-v1`, `memory-v1`, `memory-holdout-v1`, `external-v1`, `security-v1`, `ui-v1`, and `cost-v1`.

**Eighteen zero-tolerance gates** (`ZT-01`–`ZT-18`): secret exposure; ledger bypass; silent external clobber; effects outside hard policy; missing required provenance; retracted claim presented as current; replay repeating effects; approval-binding violation; integrity failure; trust-root mutation; unrecorded human authority; coverage dishonesty; consent display/token/origin tampering; unvalidated lifecycle transition; channel leak; remote request from the UI; Todo cap violation; stale source presented as current. Zero-tolerance tests never retry; a flake is a defect and the run is `blocked`.

**Twenty canonical invariants** (`I-01`–`I-20`) cover append-only records, single sequence and partial order, unknown-component round trips, desired/observed separation, human authority, immediate read-time exclusion, provenance, blob ordering, at-least-once effects and `outcome_unknown`, effect-free replay, complete approval binding, hard boundaries, canonical-write denial, atomic activation, backup/restore verification, coverage honesty, undo preservation, lifecycle validation, stable-domain authorization, and the closed channel set.

**Scenario suites:** `AS-01`–`AS-12` (ingest batches, explore intent, approve structural goal, nested deltas, external commit, memory reconciliation, retract/quarantine, declarative activation plus approved executable candidate, search channel, replay/undo, image backup/restore, ceilings/freshness); `C-01`–`C-14` (sequencing, duplicate delivery, merge races, approval batches, stale approvals, evidence dedupe, overrides, tier self-grant, clobber, cross-agent undo, concurrent effects); `R-01`–`R-07` (projection and plugin-state rebuild, presentation replay, undo, compensation); `P-01`–`P-10` (poisoning and quarantine); `B-01`–`B-12` (CAS, image backup, restore, erasure); `U-01`–`U-10` (structure, comprehension, CSP).

**Spikes and measurements** are `S3` (Monty containment), `S4` (lanes, channels, ceilings), `S5` (reconciliation and poisoning), `S6` (comprehension, interrupt grouping, CSP), `S7` (ingest batches and freshness), and `S8` (search filter). `S1` and `S2` are retired with their decisions recorded. Each live protocol cites one dataset and a pre-registered decision rule; `inconclusive` blocks the dependent decision and never becomes a default.

Phase exits require an `EvidenceEnvelope` with `outcome="pass"` for every cited identifier, or a documented accepted residual; `inconclusive` blocks and `blocked` is a defect.

### Open questions

Deferred spike decisions with fixed provisional behavior: `LIM-1` ceilings (schema and enforcement points fixed; values are operator configuration); `UI-1`/`UI-2` interface pins and interrupt grouping; `NET-1` search-internal transport; `ING-1` Access without edge TLS decryption; `LUKS-1` vTPM seal binding; `FRESH-1` freshness windows; `JUDGE-1` DLP and judge thresholds; `IMG-1` snapshot quiesce; and `D2`–`D8`. `LANG-1`, `NODE-DENO-1`, `DEP-1`, and `ISO-1` are closed or retired and recorded in the specifications rather than deferred.

Human policy questions: retention, deletion, and legal-erasure obligations beyond indefinite default; whether any local human-auth mechanism may replace Cloudflare Access for authority endpoints on loopback; what evidence would justify tightening the experimental live-plugin posture; which effect classes are non-delegable even under `automatic`; what attention and cost envelope bounds always-on operation; and which quality thresholds define acceptable reconciliation, task success, and UI usefulness.

Evidence gaps that public-source reading cannot close: comparable agent-harness outcome/retention/cost data; a matched independent memory benchmark; precision/recall for LLM contradiction detection, entity resolution, and invalidation; calibrated per-claim confidence and retraction-propagation cost; a large-scale evidence/size frontier for compaction; a portable signed semantically versioned execution-snapshot format; per-model/per-language programmatic tool-use success rates; an independent security audit of the chosen sandbox/broker composition; portable UI-state artifact standards and catalog parity; and long-term support and pricing of runtime and provider options.
